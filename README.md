# cc-quarantine-lab

CC_Codex 二期（26.11）**数据工程**产品线：**抓取隔离舱检疫台**（Pyramid + Waitress + 原生 JS SPA 右侧抽屉 + SQLite）。

## 一句话骨架

**抓取批次 → 坏件入隔离舱 → 复核放行 / 回炉重抓 → 隔离对账**

与血缘影响、压实合并、回灌切片、契约换版、水印盖印、清单闭合、留存裁撤**正交**；不做 CDC 游标 / Feed 归并 / Slicegate 类指纹。

## 领域

- **所属领域**：数据工程
- **子方向偏采集**：源站抓取结果检疫、坏件隔离、回炉重抓、隔离对账

## 页面（≥8）

## 钉批钉点口径（单读轨）

对账读轨只有一套：**切流账册**。（另一轨「双写两轨」已收口为拒开。）

- **钉批落点**：`pin_batch_ledger` 一行，钉住当刻批次号、坏件指纹与坏件数；
  `pin_batch_snapshot` 存当刻坏件的逐条指纹快照。
- **只读引用**：对账 / 抓取目录只读这套落点；对账报告写死当刻指纹，**拒回刷**。
- **单轨**：双写两轨已收口为拒绝（`双写两轨未启用…禁止双开`）；库层唯一索引兜底。
- **整笔提交**：抢 `BEGIN IMMEDIATE` 写锁后判重，一气写完落点、快照、芯片与拒回刷；
  两人同抢同一批次只有一个能成，另一人收白话 409。
- **闸**：复核放行、回炉成功、清洗编排（套规则）在执行前核
  「钉批芯片 · 对账批次号 · 钉批落点」三项；缺落点、只有芯片、指纹拧花、批次号对不齐
  一律挡住并给白话原因。

页面上分三处展示：**钉批芯片**、**对账批次号**、**钉批落点**（对账页 / 抓取目录 /
舱位卡片 / 设置页）。
